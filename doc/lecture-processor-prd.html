01 — Overview

Product Vision

Drag in a folder of lecture recordings — get back normal-speed videos, searchable transcripts, and clean slide images, all in one go.

The Lecture Processor App is a local desktop application that batch-processes lecture recordings (.mov files). The user drops a folder and selects how their recordings were captured. The app normalizes speed if needed, transcribes audio, and extracts slides — all offline, all automated.

Core Problem

Students often record lectures at 2× speed to save storage and capture more. Reviewing these recordings later is uncomfortable and transcription tools (including Whisper) perform noticeably worse on sped-up speech. This app closes that gap.

Output Structure

OutputFolder/ └── Lecture1/ ├── Lecture1.mp4 ← 1× version, keeps original lecture name (optional to save) ├── transcript.txt ├── transcript.srt ← timestamps match playback-speed video ├── slides/ │ ├── slide_0001_00-05-30.png │ └── ... └── processing_log.txt
Timestamp Rule
Timestamped outputs must match the video the user will actually play. If the normalized 1× video is saved, SRT and slide timestamps use 1× playback time. If the normalized video is not saved, timestamped outputs are converted back to the original recording's playback speed so they still line up with the available video.

FFmpeg Command (Normalization Step)

# Fast mode — atempo only (recommended for MVP)
ffmpeg -i input.mov \
  -filter_complex "[0:v]setpts=2.0*PTS[v];[0:a]atempo=0.5[a]" \
  -map "[v]" -map "[a]" \
  -c:v libx264 -preset medium -crf 23 \
  output_1x.mp4

# High-quality mode — Rubber Band for pitch-correct audio
# Use pyrubberband or FFmpeg's rubberband filter if compiled in
Edge Case — VFR Input
.mov files from screen recorders often use variable frame rate (VFR). Detect VFR before processing and convert to a constant frame rate (CFR), using fps=30 or the source's intended frame rate, before the setpts filter. Validate that end-of-file A/V drift stays under 50ms.
Edge Case — Accidental Re-normalization
If normalization is run on an already 1× file, output will be half-speed. MVP safety control: show an explicit warning and require confirmation before processing (see Screen 3 below). This reduces mistakes but does not fully prevent them; true blocking requires future speed detection.
Edge Case — Short Files (< 60 seconds)
Files under 60 seconds are skipped entirely — not processed. A warning entry is written to the batch log and the file is listed on the completion screen under a "Skipped" section with reason "File too short (<60s)".
Failure Behavior
If a file fails at any pipeline step: (1) partial output for that file is deleted, (2) the batch continues with remaining files, (3) the failure is recorded with step name and error message, (4) failed files are listed on the completion screen with their failure reason.

05 — Tech Stack

Implementation

LayerTechnologyNotes
Desktop shellTauri (preferred) / ElectronCross-platform, native file dialogs
Processing corePython (CLI)Invoked by Tauri via subprocess or sidecar
Speed normalizationFFmpeg via ffmpeg-pythonsetpts + atempo; Rubber Band for HQ mode
Transcriptionfaster-whisper (preferred) or openai-whisperMVP uses one controlled Whisper transcription queue with large-v3 loaded once. Multiple files can still be active in the pipeline while transcription jobs wait their turn.
Slide extractionOpenCV + imagehashScene change detection + dedup
Image post-processingPillowCrop, resize, export PNG
ConcurrencyThreadPoolExecutor orchestrator + subprocess media workmax_workers=n (default 4) for file-level pipeline work. FFmpeg jobs run as subprocesses, slide extraction can run in parallel, and MVP transcription uses a single Whisper lane unless an advanced multi-model mode is added for high-RAM machines.

Implementation Order

  • Phase 1 — Python CLI with --recording-speed [1x|2x] flag; validate FFmpeg normalization + VFR guard on real .mov files
  • Phase 2 — Integrate transcription (single controlled large-v3 queue) + slide extraction on normalized output; validate WER improvement; implement short-file skip (60s) and failure handling with partial output cleanup
  • Phase 3 — Add --concurrent [1-8] flag using a file-level executor; default 4; validate on M1 Max 32GB; confirm video/slide parallelism with single-lane Whisper transcription queue under load
  • Phase 4 — Tauri wrapper + all Settings modal controls; wire confirmation dialog, empty state, ✕ clear, keyboard shortcuts (⌘, / ⌘R / Escape)
  • Phase 5 — Per-file completion stats (word count, slide count); failure + skipped rows on completion screen; HQ audio mode (Rubber Band)
06 — Risks

Known Risks

RiskSeverityMitigation
A/V sync drift on VFR .mov files High Detect VFR on input; force CFR conversion before setpts
User normalizes 1× files (half-speed output) High Explicit warning + confirmation required; future speed detection needed for a hard block
atempo=0.5 at minimum boundary Med Validate input; document that only 2× is supported in MVP
Disk space — normalized video doubles size Med "Save normalized video" toggle; show estimated output size before processing
Rubber Band not installed on user machine Low Gracefully fall back to Fast (atempo) mode with inline notice
High concurrency saturating RAM on low-end hardware Low Default of 4 validated for M1 Max 32GB; UI shows hardware guidance labels (1–2 for laptops, 4 for default, 6–8 for workstations); transcription queue prevents multiple large model loads in MVP
